# 服务可靠性回移与本机验证（2026-11-13）

在源码 0.2.10 / engine 0.1.56 的定制部署上，替换停止请求、Windows 子进程启动、图片读取器就绪等待及残留进程扫描的旧实现。主模型、原生 Q4 MTP、57K 词表和 DM16 引擎保持原来的已测配置。

## 改动与复现

| 改动 | 本机旧实现 | 回移后 |
| --- | --- | --- |
| 请求停止时引擎已关闭 | 进程对象为空时报 AttributeError，输入管道关闭时报 ValueError | 四种管道/进程状态均通过，正常管道仍发送 STOP |
| Windows 包装程序立即启动后代进程 | 延迟分配作业对象时，Python 后代和 `.cmd` 启动的 Node 均残留 | 先暂停创建、加入作业对象、再恢复；后代随服务清理 |
| 图片读取器在 READY 前输出日志 | 把日志当成失败并结束读取器 | 等待 READY、ERR、进程结束或统一期限；不吞掉后续编码响应 |
| Windows 残留进程检查 | 读取所有进程的命令行 | 先按名称筛选，再核对实际文件、命令行和父进程身份 |

旧实现的八项对照测试中，**2 项通过、6 项失败或报错**。同一组测试在部署代码上全部通过。新增回归还覆盖嵌套 Windows 作业对象、分配被拒绝、启动期间异常、标准输入输出、启动参数传递、图片读取器超时/提前退出和非 UTF-8 启动日志。

上游来源：[停止异常](https://github.com/Niko1221/Strata/commit/bbf97633c8de03a7f6258bc7f68d0be4eb40bcfc)、[Windows 子进程生命周期](https://github.com/Niko1221/Strata/commit/5d87c4d8eb9d536c663698fdc38a9fc90537090a)、[Windows 错误文字后续修订](https://github.com/Niko1221/Strata/commit/ca9c53c1fd865651aafd639e9f74a80e8461f6e8)、[图片就绪等待](https://github.com/Niko1221/Strata/commit/4cce1ee4d0057ff718cb0219e0114e5ddf73f296)、[进程扫描](https://github.com/Niko1221/Strata/commit/79d529cc78a2c40a516dbd012636125f0a95b873)。

## 启动检查耗时

在本机交替执行旧/新只读进程扫描各三次，两者均发现 0 个残留进程。旧实现首轮为 5.646 秒，随后 0.132/0.113 秒；新实现三轮为 0.069/0.066/0.063 秒。中位数为 **0.132 → 0.066 秒**。首轮冷启动条件不同，不把 5.646 秒与新实现热扫描直接算提速百分比。这也不是模型加载总时间或输出 TPS 的提升。

## 部署、清理与限制

正式服务已停止并重新启动，验证了新进程、选定 Python 源码和唯一的主引擎/视觉读取器。主引擎仍为 `strata-native-mtp-dm16.exe`，SHA-256 `52a3e0d073342ff6cc102a1a0c948a189c055d78b6f6db2397dbd99ff8496519`。Python 修复没有改变原生引擎二进制；本轮未重跑长上下文吞吐，也不声称 TPS 提高。

公网兼容服务在通用服务之外还有既有适配层。部署时只替换核验一致的引擎类、视觉类和错误说明函数，保留适配层；其余三个修改模块与 fork 一致。没有用 fork 的整个 server.py 覆盖定制适配入口。

旧实现已原位替换。本轮临时测试执行器、源码副本、回退副本和生成的试验配置在验收后清理，输入、结果及源码差异保留。之前清理的 8 个目标也重新核验不存在；详情见 [清理与保留目录](../CLEANUP.md) 和本目录 JSON 数据。自动回归测试保留在源码中。

验证平台为 Windows 11 / Ryzen AI Max+ 395 / gfx1151；未在 Linux、macOS 或其他 GPU 上执行本轮测试。进程名称筛选沿用上游范围：手动给引擎建立另一个名称的硬链接时，不保证被 Windows 快速残留扫描找到。
