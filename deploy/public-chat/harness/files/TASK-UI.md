# 待办组件约定

待办进度行和清单共享一张后层卡片，原输入框是前层卡片。后层卡片左右各缩进 14px，收起时露出约 32px 高；进度按钮高 30px。两张卡片以 32px 深度交叠，前层只覆盖待办卡片下沿留白，不覆盖进度或操作。输入框原有外观、尺寸、按钮和内层结构保持不变。用户只操作「展开 / 收起」。展开时卡片向上增加高度，进度行、输入框和阅读位置保持稳定；输入、发送和停止始终可用。

## 数据与职责

| 部分 | 职责 | 不承担的职责 |
| --- | --- | --- |
| 消息的 `taskList` | 保存服务端已提交的任务快照，随消息分支保留 | 不保存界面尺寸或展开状态 |
| `task-state.js` | 从当前分支选取快照，计算计划归属、完成数及展示状态 | 不访问 DOM、IndexedDB 或全局运行状态；不修改输入 |
| `chat-records.js` | 在读取/保存边界规范界面偏好，兼容旧的高度字段 | 读取不回写数据库，不改变记录时间 |
| `task-view.js` | 渲染当前卡片和历史清单，处理用户展开/收起命令 | 渲染不保存记录、不修改待办、不执行工具 |
| `chat-layout.js` | 根据实际内容测量输入区，处理键盘和可视视口 | 不为待办复制固定的占位高度 |

发送给模型的任务、实时卡片和历史清单读取同一份消息快照。历史清单的完成数和状态名称共用 `TaskState`。工具结果接收后更新消息，再通知界面刷新。

## 状态与归属

展示状态只有隐藏、收起、展开。隐藏由数据决定，收起/展开由用户偏好决定。

| 条件 | 结果 |
| --- | --- |
| 没有已提交清单，或最近清单为空 | 隐藏 |
| 新计划第一次出现 | 收起 |
| 同一计划更新、跨轮继续、刷新恢复 | 使用该计划的展开偏好 |
| 全部完成的当轮 | 保留完成数量，仍可展开 |
| 完成后用户再发问 | 隐藏入口，历史和模型上下文仍保留最后快照 |
| 随后保存另一份计划 | 新计划默认收起 |
| 停止或出错 | 保留未完成任务，显示暂停或中断 |

计划归属由当前消息分支中这一连续计划的首份快照标识确定。完成后下一次提问、或显式清空清单，会结束这段计划的展示范围。`chat.taskPanel` 只存 `{ open, scope }`，不再保存半屏或全屏档位。旧偏好在记录边界转换，原始存储记录在正常保存前保持不变。

滚动位置是视图临时状态，按会话对象和计划归属保存；不进入模型提示词或数据库。删除会话后相应对象可被回收。

## 布局与交互

两张卡片在 `composer-stack` 的同一个网格中组合：待办位于后层，输入框位于前层，共享一条由 `--task-overlap` 定义的重叠轨道。待办下沿预留相同深度的留白。布局规则只控制叠放位置，不覆盖输入框原样式，不依赖负边距或固定高度空壳。清单区通过 `data-composer-expansion` 标记可展开内容。布局管理器测量整个输入区，并扣除展开内容来计算对话尾部预留空间，因此展开不触发历史跳动，字体和输入框高度改变时也能重新计算。

清单短时按内容定高，长时以 240px 和可视区域剩余高度中的较小值为上限并内部滚动。展开按钮箭头向上，收起按钮箭头向下。键盘导航从进度行进入清单，再进入输入框；不锁焦点、不设置遮罩。清单或进度行内按 Escape 可收起。进度更新不自动展开、不重建未变化的条目、不移动阅读位置。

## 修改与验收顺序

修改组件前先核对本文件中的行为与职责；需求变化时先更新约定。随后修改对应责任模块并移除被替代的实现。不能通过在渲染中回写偏好、另存任务副本、增加尺寸档位或复制固定占位高度来处理局部症状。

从应用 `server/` 目录执行：

```text
npm run test:tasks-ui
node --test tests/generation-recovery-browser.test.js tests/conversation-memory.test.js tests/browser-context.test.js
node tests/chat-layout.test.js
npm run check
```

验收既检查状态与恢复，也检查完整界面：前后卡片交叠、原输入框不变、入口固定、清单与进度行无间隙、字体变大、多行输入、键盘视口、刷新与会话切换。发布前查看浏览器截图，通过正常输入发送路径验证；发布后核对静态文件哈希并记录实际模型验收结果。自动检查不能替代交互效果审查。

## 退出、切换与历史恢复

任务快照属于消息，展开偏好属于该会话中的当前计划。即使不同会话的任务 ID 相同，也不共用内容、展开状态或临时滚动位置。后台任务提交到原会话；查看另一会话时不会改写正在查看的卡片。没有任务的新会话保持隐藏。查看历史只读，不触发模型、工具或更新时间戳。

浏览器 IndexedDB 保存已提交的会话；同一浏览器中刷新、关页重进、页面崩溃后重新启动浏览器，都从保存记录恢复。生成中离开页面不代表停止；重进通过原生成编号续传。压缩前已保存但尚未提交的请求可恢复准备流程；服务端重启导致事件流过期时取回已持久化的任务检查点并显示中断，由用户继续。完整历史不自动跨设备同步。

`task-lifecycle-browser.test.js` 实际检查历史面板切换、同名任务隔离、空会话重载、删除后重载、页面崩溃、持久浏览器配置重启、收起后立即刷新，以及关页期间后台更新并恢复到另一会话；结合 `task-resume-browser.test.js` 和 `generation-recovery-browser.test.js` 检查压缩前退出、工具执行后退出、断网、停止和恢复不重放。崩溃测试针对已提交记录，不把尚未落盘的数据视为已保存。
